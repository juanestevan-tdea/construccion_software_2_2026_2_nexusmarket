# Requisitos No Funcionales

| ID | Categoría | Requisito | Evidencia en el código |
|----|-----------|-----------|------------------------|
| RNF-001 | Seguridad | Autenticación stateless mediante JWT firmado explícitamente con HMAC-SHA256 (JJWT 0.12.6), expiración de 24 h por defecto (`JWT_EXPIRATION`, `86400000` ms). Las contraseñas se almacenan con BCrypt. `JWT_SECRET` es obligatorio, sin fallback, y debe tener al menos 256 bits de entropía; la aplicación falla al arrancar si falta o es demasiado corto. | `infrastructure/security/JwtService.java`, `application.properties` (`jwt.secret=${JWT_SECRET:}`, `jwt.expiration=${JWT_EXPIRATION:86400000}`), `SecurityConfig` (`SESSION_STATELESS`). |
| RNF-002 | Seguridad | Autorización basada en roles (RBAC) con 5 roles: `BUYER`, `SELLER`, `WAREHOUSE_OPERATOR`, `ADMIN`, `SUPERVISOR`. Endpoints protegidos salvo `/api/v1/auth/register`, `/api/v1/auth/login` y `/actuator/health`. Las anotaciones `@PreAuthorize` están activas mediante `@EnableMethodSecurity`. Fallos de autenticación/autorización devuelven `401` / `403` con `ErrorResponse`. | `SecurityConfig.java`, `domain/valueobjects/UserRole.java`, `RestAuthenticationEntryPoint`, `RestAccessDeniedHandler`. |
| RNF-003 | Seguridad | Validación de entrada con Jakarta Bean Validation (`@NotBlank`, `@Email`, `@Size`, `@DecimalMin`, `@Min`, `@NotNull`) y manejo centralizado de excepciones en `GlobalExceptionHandler` sin filtrar stack traces al cliente. | DTOs `adapters/rest/dtos/requests/*`, `GlobalExceptionHandler.java`. |
| RNF-004 | Rendimiento | Las consultas de catálogo (productos, categorías, bodegas, resumen `/api/v1/catalog`) deben responder por debajo de 200 ms (p95) en entorno de desarrollo con datos en caliente. Creación de orden y checkout por debajo de 500 ms. | No hay medición automatizada en el código; criterio de diseño. |
| RNF-005 | Disponibilidad | La aplicación es stateless (sin sesiones HTTP: `SessionCreationPolicy.STATELESS`). Los contenedores de Docker Compose usan `restart: unless-stopped` para MySQL, MongoDB y la app. | `SecurityConfig.java`, `docker-compose.yml`. |
| RNF-006 | Disponibilidad | Transacciones ACID en MySQL para operaciones críticas (órdenes, inventario, facturas) a través de `@Transactional` en los servicios de dominio. | `domain/services/*.java` (`@Service`, `@Transactional`), `spring.jpa.*` en `application.properties`. |
| RNF-007 | Mantenibilidad | Arquitectura hexagonal: los modelos, value objects y excepciones del dominio no importan JPA, MongoDB, Jackson ni HTTP. Los contratos de entrada son los 16 `*UseCasePort` (con modelos `*Command`/`*Result` propios) y de salida los 14 `*RepositoryPort`; 28 servicios de dominio con responsabilidad única contienen la lógica de negocio. | `domain/`, `adapters/useCases/`, `DOCUMENTATION.md` ("Regla de Oro del Dominio"). |
| RNF-008 | Mantenibilidad | Suite de pruebas automatizadas: 211 tests verdes (JUnit 5, Mockito, Spring Test) que cubren servicios de dominio, controladores y seguridad JWT. | `src/test/`, `DOCUMENTATION.md` §10, `README.md`. |
| RNF-009 | Observabilidad | Auditoría inmutable de operaciones en MongoDB (`AuditLog`) con usuario, entidad, acción y timestamp, consultable por rango de fechas. Logs de la aplicación vía SLF4J. | `domain/models/AuditLog.java`, `adapters/persistence/mongodb/`, `GlobalExceptionHandler` (logging de errores). |
| RNF-010 | Observabilidad | Endpoints de salud del sistema expuestos por Spring Boot Actuator (`/actuator/health`), accesibles sin autenticación. | `pom.xml` (`spring-boot-starter-actuator`), `SecurityConfig` (`PUBLIC_ENDPOINTS`). |
| RNF-011 | Interoperabilidad | API REST sobre JSON (`application/json`), códigos de estado HTTP semánticos (200, 201, 204, 400, 401, 403, 404, 409, 422, 500) y cuerpo de error estandarizado (`ErrorResponse`). | `GlobalExceptionHandler.java`, `ErrorResponse.java`. |
