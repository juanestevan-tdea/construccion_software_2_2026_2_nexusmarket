# Requisitos No Funcionales

| ID | Categoría | Requisito | Evidencia en el código |
|----|-----------|-----------|------------------------|
| RNF-001 | Seguridad | Autenticación stateless mediante JWT firmado con HMAC-SHA256 (JJWT 0.12.6), expiración de 24 h (`86400000` ms). Las claves se almacenan con BCrypt. En producción es obligatorio inyectar `JWT_SECRET` con al menos 256 bits de entropía; el valor de `application.properties` es solo fallback de desarrollo. | `infrastructure/security/JwtService.java`, `application.properties` (`jwt.secret=${JWT_SECRET:...}`, `jwt.expiration=86400000`), `SecurityConfig` (`SESSION_STATELESS`). |
| RNF-002 | Seguridad | Autorización basada en roles (RBAC) con 5 roles: `BUYER`, `SELLER`, `WAREHOUSE_OPERATOR`, `ADMIN`, `SUPERVISOR`. Endpoints protegidos salvo `/api/auth/**`, swagger y actuator health. Fallos de autenticación/autorización devuelven `401` / `403` con `ErrorResponse`. | `SecurityConfig.java`, `domain/valueobjects/UserRole.java`, `RestAuthenticationEntryPoint`, `RestAccessDeniedHandler`. |
| RNF-003 | Seguridad | Validación de entrada con Jakarta Bean Validation (`@NotBlank`, `@Email`, `@Size`, `@DecimalMin`, `@Min`, `@NotNull`) y manejo centralizado de excepciones en `GlobalExceptionHandler` sin filtrar stack traces al cliente. | DTOs `adapters/rest/dtos/requests/*`, `GlobalExceptionHandler.java`. |
| RNF-004 | Rendimiento | Las consultas de catálogo (productos, categorías, bodegas, resumen `/api/catalog`) deben responder por debajo de 200 ms (p95) en entorno de desarrollo con datos en caliente. Creación de orden y checkout por debajo de 500 ms. | No hay medición automatizada en el código; criterio de diseño. |
| RNF-005 | Disponibilidad | La aplicación es stateless (sin sesiones HTTP: `SessionCreationPolicy.STATELESS`). Los contenedores de Docker Compose usan `restart: always` para MySQL, MongoDB y la app. | `SecurityConfig.java`, `docker-compose.yml`. |
| RNF-006 | Disponibilidad | Transacciones ACID en MySQL para operaciones críticas (órdenes, inventario, facturas) a través de `@Transactional` en los servicios de dominio. | `domain/services/*.java` (`@Service`, `@Transactional`), `spring.jpa.*` en `application.properties`. |
| RNF-007 | Mantenibilidad | Arquitectura hexagonal: el dominio no importa JPA/MongoDB/Jackson/HTTP. Los contratos de entrada son los 15 `*UseCasePort` y de salida los 13 `*RepositoryPort`; 20 servicios de dominio contienen la lógica de negocio pura. | `domain/`, `adapters/useCases/`, `DOCUMENTATION.md` ("Regla de Oro del Dominio"). |
| RNF-008 | Mantenibilidad | Suite de pruebas automatizadas: 94 tests verdes (JUnit 5, Mockito, Spring Test) que cubren servicios de dominio y controladores. | `src/test/`, `DOCUMENTATION.md` §9, `README.md`. |
| RNF-009 | Observabilidad | Auditoría inmutable de operaciones en MongoDB (`AuditLog`) con usuario, entidad, acción y timestamp, consultable por rango de fechas. Logs de la aplicación vía SLF4J. | `domain/models/AuditLog.java`, `adapters/persistence/mongodb/`, `GlobalExceptionHandler` (logging de errores). |
| RNF-010 | Observabilidad | Endpoints de salud del sistema expuestos por Spring Boot Actuator (`/actuator/health`), accesibles sin autenticación. | `pom.xml` (`spring-boot-starter-actuator`), `SecurityConfig` (`PUBLIC_ENDPOINTS`). |
| RNF-011 | Interoperabilidad | API REST sobre JSON (`application/json`), códigos de estado HTTP semánticos (200, 201, 204, 400, 401, 403, 404, 409, 422, 500) y cuerpo de error estandarizado (`ErrorResponse`). | `GlobalExceptionHandler.java`, `ErrorResponse.java`. |
